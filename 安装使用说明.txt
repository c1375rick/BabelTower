Babel Tower - Deadlock 聊天翻译 Mod 安装使用说明
=================================================

本 Mod 由两部分组成:
  1. 游戏内部分(pak01_dir.vpk)—— 聊天翻译界面
  2. 本地桥(core + portable-node)—— 负责调用翻译接口(免 Key,免费)

两步都要装,缺一不可。

--------------------------------------------------
一、安装(约 3 分钟)
--------------------------------------------------

1. 把整个文件夹解压到你喜欢的位置(路径可含中文,但不要带空格,如 D:\BabelTower)

2. 安装游戏内 Mod —— 槽位固定为 addons\pak15_dir.vpk,按下面三步做:
   **① 先完全退出 Deadlock**(游戏运行中覆盖会留下损坏的半截 VPK)
   **② 把 addons 里现有的 pak15_dir.vpk 改名备份**(如 pak15_dir.vpk.bak-日期)
   **③ 再把包里的 pak01_dir.vpk 改名为 pak15_dir.vpk 放进去**

   方法 A(推荐):打开 Deadlock Mod Manager 导入 pak01_dir.vpk
      (同样要先退出游戏、先备份旧文件)
   方法 B(手动):
      把 pak01_dir.vpk 重命名为 pak15_dir.vpk,复制到
      <你的Steam库>\steamapps\common\Deadlock\game\citadel\addons\

   注意:如果该目录已有我们旧版的 vpk,**覆盖它**,不要改成 pak25_dir.vpk
   另存一份 —— 新旧两份 mod 同时加载会导致界面重复、行为错乱。

3. 启动本地桥(二选一):
   方法 A(推荐,一劳永逸):**双击 BabelTower-维护菜单.bat → 选 5**(安装开机自启)
     之后开机自动启动桥;桥常驻不随游戏退出(2026-08-12 起),什么都不用管。
     卸载自启:BabelTower-维护菜单.bat → 选 6
   方法 B(临时):双击 StartDeadlock.bat(每次玩之前都要双击一次)

3.5【可选,但强烈建议】开低延迟通道 —— 双击 **BabelTower-维护菜单.bat → 选 1**(一键安装)
   不做这步也完全能用,只是译文会慢(3~27 秒)。做了之后实测**约 1 秒以内**
   (服务端只占 0.06 秒,余下是游戏内页面加载 + 0.3 秒的结果轮询粒度)。

   它做三件事:检查环境 → 问你要不要信任一张本机证书 → 起桥并自检。
   证书只加到**当前 Windows 用户**的信任库(不碰系统级/企业级),用途是让游戏内
   隐藏 HTML 面板能加载本机 https 页面 —— 那是低延迟回程的唯一拦点
   (引擎报 error:-202 = ERR_CERT_AUTHORITY_INVALID)。

   ⚠ 它会请你确认后才写入信任库。输入 YES 继续;不确认就直接跳过,
     翻译仍然走原来的通道,功能不受影响。

   ⚠ 它**不需要管理员权限**。证书写的是"当前用户"的库,Steam 和游戏用同一个
     Windows 用户跑就行。**别把 Steam 或游戏设成"以管理员身份运行"** ——
     提权解决不了证书问题,只会平白多一次 UAC。

   ⚠ 走完这一步之后必须:**完全退出 Steam(托盘图标也退掉)→ 重新打开 Steam**。
     信任库由 Steam 宿主缓存,**只重启游戏是不生效的**(2026-10-15 实测,见下)。顺序不能换。

   ⚠ **撤销信任也一样要完全重启 Steam**(同一条机制)。证书从库里删掉之后,
     正在运行的 Steam 仍会继续信任它 —— 2026-10-15 实测:证书已删、
     游戏仍报 ALIVE,直到把 Steam 完全退出重开才变成 `not usable`。
     **证书的加和减都不是即时生效的。**

   怎么确认生效:进对局发一条消息,看游戏 console.log 里有没有这一行
     `[LCT] https panel: ALIVE`
   有 = 低延迟通道已启用;出现 `https panel: not usable` = 还没生效,
   把那一行连同 logs\install_babeltower.log 一起反馈给我们。

   不想用/要撤销:运行
     powershell -ExecutionPolicy Bypass -File scripts\gen_bridge_cert.ps1 -Untrust
   只看现状(什么都不改):BabelTower-维护菜单.bat status

   提示:addons 目录里**只能有一份**我们的包。同时存在新旧两个(如 pak15 与
   pak90)会导致界面重复、行为错乱 —— 新旧两份 mod 同时加载就是这个后果。

3.6 更新到新版本 —— 双击 **BabelTower-维护菜单.bat → 选 2**(更新)

   它只从官方 GitHub Releases 取包,不从别处下载:
     ① 查 api.github.com/repos/c1375rick/BabelTower/releases/latest
     ② 只认文件名严格匹配 BabelTower-<版本>-win64.zip 的资产(不做模糊匹配)
     ③ 下载后**先校验体积、再校验 SHA256**,两者任一不符就拒绝安装
     ④ **游戏正在运行时只下载、不安装**(运行中替换会留下损坏的半截文件);
        退出游戏后重跑一次即完成安装
     ⑤ 换包前自动备份旧包,换完校验 SHA256,失败自动回滚
     ⑥ 覆盖安装目录时保留你的 config.json / 词典 / quickchat / logs

   常用参数(BabelTower-维护菜单.bat update 后面加):
     -Check         只看有没有新版,不下载不安装
     -DownloadOnly  只下载并校验(网慢时先下好,之后离线装)
     -Force         版本相同也重装
   退出码:0 已最新或更新成功 / 2 有新版但未安装 / 1 失败

   注意:若官方那个版本没有提供 SHA256,脚本**默认拒绝**安装并提示;确实要装
   才加 -AllowNoDigest(自行承担风险)。我们不发布无法校验的包。

3.7 检测/诊断 —— 双击 **BabelTower-维护菜单.bat → 选 4**(诊断,只读,不改任何东西)

   一次摊开:Node 与安装目录完整性、桥是否在跑(版本/provider/日志目录)、
   config 是否可解析与有没有配 Key(**只查有没有,不读值**)、证书是否已生成
   与是否受信、https 端口是否通、游戏是否在跑、console.log 是否新鲜(这决定
   桥能不能收到消息)、addons 里我们的包是哪一个(按内容标记认,不靠文件名)、
   历史残件有多少占多少空间、开机自启、磁盘余量。
   每条都带**判据**,方便你自己核对,而不是让你猜。
   报告会落盘到 logs\diagnose_<时间>.txt,并已**脱敏**(Key/长串一律打码)——
   可以放心截图或发给我们。

   退出码:0 关键项全过 / 1 有关键项失败(报告里会列出)

3.8 卸载 —— 双击 **BabelTower-维护菜单.bat → 选 3**(卸载,默认保守)

   一次处理五处:mod 包、开机自启、常驻的桥与 https 终结进程、信任库里的
   本机证书、%LOCALAPPDATA%\BabelTower 的证书状态。**认包靠内容标记**,所以
   不会误删别人的 pak。
   先列现状再逐项确认;删历史残件与删状态目录要额外加 -PurgeBackups / -PurgeState
   (不可逆)。加 -List 则只列现状、什么都不改。
   要恢复:重新解压发行包 + 双击 BabelTower-维护菜单.bat → 选 1。

4. 给 Deadlock 加 -condebug 启动参数(必做,只需设置一次):
   Steam 库 → Deadlock 右键 → 属性 → 常规 → 启动选项 → 填 -condebug

   为什么必做:
     游戏只有带这个参数启动,才会生成 console.log 文件;而本地桥唯一能收到
     游戏消息的途径就是读这个文件。不设它,翻译链路完全不工作 —— 而且是
     静默失效:游戏里 /tr 能开、设置能存、看起来一切正常,但你的消息根本
     没送到桥,logs\bridge.log 里一条消息流量都没有。

   - 用第 3 步方法 B(StartDeadlock.bat)启动游戏的,已自动带上该参数,可跳过本步;
   - 用方法 A(开机自启)+ 自己从 Steam 正常启动游戏的,必须手动设一次;
   - 怎么确认生效:游戏跑起来后看 logs\bridge.log,应有一行
     `game console.log found: ...`;若出现 `[warn] 缺少 -condebug`,
     按上面的路径补设一次即可(设一次永久生效)。

5. 启动游戏,进任意一局(训练场也行):
   - 按 Enter 打开聊天,输入 /tr 回车 → 浏览器自动打开**网页设置页**
     (http://127.0.0.1:8791/ui);网页里点"测试连接"应显示成功
   - 点"保存到 config.json";**游戏里 1 秒内生效,不用重启游戏**
   - 大功告成!队友发外语消息,下方会显示金色中文译文

--------------------------------------------------
二、设置说明(网页设置页)
--------------------------------------------------

  打开方式:聊天输入 /tr 回车(用系统默认浏览器打开网页);
            另有一个游戏内旧面板:输入 /tr panel 回车,或点聊天框右侧"译"按钮
            (旧面板是调试/兜底用的:它读的是开机缓存,改完要重启游戏才刷新)

  网页设置页分四块:

  - 翻译服务    服务商 bing(免Key,默认)/ microsoft(Azure Key)/ deepl / OpenAI兼容 / google
                API Key/区域/回退链/超时/源语言/目标语言
                Key 只存在本机 config\config.json,页面上永远打码显示
  - 游戏内行为  翻译总开关(关掉后收发都不翻)/ 显示模式 / 发送前翻译 /
                发送目标语言 / 强制翻译 / 游戏侧等待超时
                ← 这一块保存后游戏 1 秒内生效
  - 通道健康    实时显示游戏↔桥的四条通路(BTIPC下行/上行、HTML桥页加载、桥页取数)
                最近一次活跃时间;全是"从未"= 游戏还没连上桥
  - 高级        整份配置(打码 JSON)可手动编辑保存

  页面语言:右上角可切换(简体中文/繁體中文/English/日本語/한국어/Français/Deutsch/
  Español/Русский/Português (Brasil));默认**跟随游戏界面语言**。

--------------------------------------------------
三、常见问题
--------------------------------------------------

Q: 译文显示"本地桥未运行"?
A: 桥没启动。确认第 3 步做了:要么装了自启(重启电脑后生效),要么双击了 StartDeadlock.bat。
   也可以直接双击 restart_bridge.bat 一键重启并自动健康检查。

Q: 双击 portable-node\node.exe 只出现一个 "> " 提示符的窗口?
A: 那是 Node.js 的命令行控制台,不是启动器,直接关掉。启动桥请用
   BabelTower-维护菜单.bat / StartDeadlock.bat / restart_bridge.bat,不要直接双击 node.exe。

Q: 开机时弹窗 "Windows Script Host 80070002 系统找不到指定的文件"?
A: 旧版自启脚本对含中文的解压路径(如 D:\Bandizip\解压\)兼容有问题。
   用 BabelTower-维护菜单.bat → 选 5 重装一次即可修复(1.0.5 起的自启脚本自动适应任意路径),
   然后重启电脑验证。

Q: 点测试显示失败?
A: 先确认桥在运行;再确认网络能访问 bing.com(公共接口,偶尔抽风会自动重试)。
   一直失败可把服务商切到 microsoft 并填自己的 Azure Key。

Q: StartDeadlock.bat 窗口一闪就没了,或桥总是起不来?
A: 双击 run-bridge.bat(诊断启动器):它前台运行桥,报错会停在窗口里不会闪退。
   常见原因:解压不完整(core 目录缺文件)。请重新解压完整安装包,不要删除 core 里任何文件。
   崩溃详情在 logs\bridge.log,反馈问题时请附上这个文件。

Q: 双击某个 .bat 提示 Missing file: xxx?
A: 启动器做了入口自检:缺哪个文件就直接点名,不再抛 PowerShell 红字然后窗口一闪而过。
   这说明安装包没解压完整(或 core\ / scripts\ 被删)——重新解压完整 zip,
   保持目录结构,不要删 core 和 scripts 里的任何文件。

Q: 游戏里没反应?
A: 确认 VPK 装到了 addons 目录且游戏完全重启过;确认 /tr 能打开网页设置页
   (浏览器弹出 http://127.0.0.1:8791/ui);若网页打不开,先双击 restart_bridge.bat 重启桥。

Q: 网页里改了设置,游戏里没反应?
A: 看游戏内 logs(游戏目录 game\citadel\console.log)或桥的 logs\bridge.log:
   - 出现 `cfg watch(push): applied …` → 下发正常(1 秒内)
   - 只出现 `cfg watch: bridge config changed` → 推送没挂上,正在走 15 秒轮询兜底,
     延迟变大但功能正常;重启一次游戏通常恢复
   - 两条都没有 → 游戏没连上桥,看网页顶部「通道健康」卡片

Q: 网页设置页打不开(浏览器没反应)?
A: 桥没在运行。双击 restart_bridge.bat;或用浏览器直接访问
   http://127.0.0.1:8791/ui 看是否出页面。

Q: /tr 能开、设置能存,但队友的外语消息不翻译;logs\bridge.log 里也看不到自己发的消息?
A: 基本可以断定是游戏没带 -condebug 启动参数(见安装第 4 步)。游戏不带它就不生成
   console.log,桥收不到游戏的任何消息,翻译链路静默失效。
   修复:Steam 库 → Deadlock 右键 → 属性 → 常规 → 启动选项 填 -condebug(设一次即可),
   然后完全重启游戏。或改用 StartDeadlock.bat 启动(已自动带该参数)。
   判据:logs\bridge.log 里出现 `game console.log found: ...` 即正常;
   若看到 `[warn] 缺少 -condebug`,说明参数没生效,或设完后游戏没完全重启。

Q: 想卸载?
A: 游戏部分:Mod Manager 里禁用/删除,或删掉 addons 里对应的 vpk。
   自启部分:powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1 -Action Remove

--------------------------------------------------
四、目录结构
--------------------------------------------------

  pak01_dir.vpk          游戏内 Mod(装进 Deadlock addons)
  core\                  本地翻译桥(不要删)
  portable-node\         内置 Node.js 运行时(不要删)
  BabelTower-维护菜单.bat        双击打开维护菜单(安装/更新/卸载/诊断/自启开关)
  restart_bridge.bat     一键重启桥 + 健康检查(桥没起来先点它)
  run-bridge.bat         诊断启动器(报错不闪退;反馈问题前先跑它)
  StartDeadlock.bat      手动启动(桥 + 游戏)
  scripts\autostart.ps1  自启/卸载脚本(由上面的 bat 调用,无需手动执行)
  scripts\restart_bridge.ps1  重启桥(由 restart_bridge.bat 调用)
  scripts\bridge_health.ps1   健康检查(由 StartDeadlock.bat 调用)

更多说明见 README.md;源代码与构建方法见 GitHub 仓库。

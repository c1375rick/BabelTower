## 0. 一句话

**CEF 不是门槛,证书才是;证书也不是 CEF 的门槛,而是"页面从本机同源加载"这个选择的门槛。**

所以默认形态定为**公网托管页(零证书)**;本机桥降为"高级 / 离线 / 隐私"模式;BTIPC 保持保险定位、不再当快路优化。

## 1. 事实基线(真机已验,不是推断)

| 事实 | 证据 |
| --- | --- |
| CEF 面板是**通用 Chromium**,可加载公网 https(与游戏内新闻/商店同机制) | POC S1:`github.io` 托管页 **2/2** 启动成功,加载→`title` 同秒(<1s) |
| 被引擎拦的是 **`http` scheme**,不是"本地/远程" | 6726 起 `http://` 一律失效;公网 `https://` 正常(见 §2.4) |
| 公网页同样跑得通 hash ↔ title 回环 | POC S2:**12/12** 按序,RTT min 2 / avg ~11 / max 24 ms |
| `localStorage` 跨**游戏重启**持久 | POC S3:`bootCount` 1→2,值读回一致 |
| CEF 内 CORS **大面积放行** | POC S4:`edge.microsoft.com`(免 Key)200、`mymemory` 200;`openai` 401、`google` 400、`libretranslate` 400 的**响应体可读** |
| 仅 DeepL Free / `terraprint` 被 CORS 拦 | 同上(`Failed to fetch`,无 `ACAO`) |

> **关键更正**:6739/6740 记的"公网 https 也全灭"是**打空**(当次本地没监听、根本没发出 https 请求),
> 见 [btipc-https-v1.md](btipc-https-v1.md) §2.4。这条曾经把路线 ③ 误判成不可行。
> 同一次修正还带来一个结论:**CORS 不能用普通浏览器推断**(应用内 Chromium 因代理给出
> `ERR_TUNNEL_CONNECTION_FAILED`,与真机 CEF 结论相反),只能真机测。

## 2. 成本口径:用户动作数

**北极星指标:从零到看见第一句译文,用户要做几个动作?其中有没有"重启 Steam/系统"这类反直觉动作?**

| 形态 | 动作序列 | 手工步数 | 含重启? |
| --- | --- | --- | --- |
| ① 本机桥(现状主路) | 装 vpk → 装证书 → **完全重启 Steam** →(桥由启动器自动拉起) | **3**(+1 自动) | ✅ **是** |
| ③ 纯托管页(无服务) | 装 vpk →(可选)填 Key | **1–2** | ✗ 否 |
| ③′ 公网同源中继 | 装 vpk →(可选)填 Key | **1–2** | ✗ 否 |

> "完全重启 Steam"是最大流失点:信任库由 **Steam 宿主**缓存,只重启游戏不生效。
> 这不是实现缺陷,是**自签证书路线的固有成本** —— DeadlockTranslate 0.7.0 同样栽在这一步
> (其 README 把"装证书/重启 Steam"列为首要失败面)。
>
> 结论:凡是把"证书 + 重启 Steam"放在**默认路径**上的方案,无论架构多优雅,都应视为高流失。

## 3. 三形态对照

| | ① 本机桥 | ③ 纯托管(无服务) | ③′ 公网同源中继 |
| --- | --- | --- | --- |
| 页面来源 | `https://localhost:8792`(自签 CA 链) | 公网静态页(公共 CA) | 公网服务(公共 CA) |
| 证书安装 | **必须**(+完全重启 Steam) | 零 | 零 |
| 同源 fetch | ✅ 天然同源 | ✗ 跨域,受上游 `ACAO` 约束 | ✅ 同源(页面调自己的 `/translate`) |
| API Key 位置 | 桥侧(页面拿不到) | 页面 / `localStorage` | 服务端(可不下发) |
| 免 Key 能力 | 有(桥侧中继 + 多上游切换) | 靠上游自行放行 CORS(实测可行,但脆弱) | 有(服务端中继,同 ①) |
| 诊断 | `bridge.log` 全量 | **黑暗**,只能靠 `title` 回传 | 服务端日志(含聚合) |
| 配置真源 | `config/config.json` | `localStorage`(清缓存/重装会丢) | 服务端 + 本地缓存 |
| 离线可用 | ✅(本机服务) | ✗(页面都要下载) | ✗ |
| 更新成本 | 换 vpk / 换桥 | 改网页即可 | 改服务即可 |
| 主要风险 | 证书安装流失、Steam 信任库 | 托管单点 + 上游 CORS 变更 + 无诊断 | 运营成本、消息过第三方、集中式单点 |

## 4. 为什么把 ③′ 也摆上台面

我们过去只在"①桥"和"③无桥"两端做取舍,漏了中间形态。而 **DLT 的架构其实已经把这个中间形态做出来了,只是放在本机**:
页面调 Kestrel 的同源端点,由服务端去碰上游。把那个"代理"从本机搬到公网,就同时吃掉两端的短板:

- 证书成本归零(公共 CA,与 ③ 相同);
- CORS 问题消失(同源,与 ① 相同);
- Key 可留在服务端(与 ① 相同);
- 诊断回到自己手上(与 ① 相同);
- 更新不动 vpk(与 ③ 相同)。

**但它是把成本换了个口袋,不是消灭成本。** 新账有三笔,必须在做之前认:

1. **运营成本与滥用面**:要有人付流量、扛限流、处理被刷(免 Key 端点一旦公开,就是公共资源)。
2. **隐私与合规**:玩家聊天正文会经过你的服务器 —— 这从"本地处理"变成了"数据处理者",
   需要明示、最小化留存、以及"可完全本地"的退出选项。
3. **集中式单点**:域名/证书/账单任一挂掉 = 全用户失联,且比 GitHub Pages 单点更集中
   (Pages 至少有全球 CDN 与多副本)。

因此 ③′ 是**可选项而非默认**;默认仍应是 ③(纯静态托管、无服务端、无数据处理者身份)。

## 5. 决议

| 项 | 决定 |
| --- | --- |
| **默认形态** | **③ 纯托管页**:装 vpk →(可选)填 Key。免 Key 上游优先,Key 为可选增强 |
| **高级模式** | **① 本机桥**,定位改为"离线 / Key 不出机 / 需要全量诊断"的用户主动选择,不再作为默认安装路径 |
| **保险** | **② BTIPC 原样保留**,只保活、不再当快路继续优化(10-29 它是唯一存活通道,保费已付) |
| **可选增强** | **③′ 公网中继**,仅在"免 Key 稳定性"或"Key 集中管理"成为真实诉求时启动 |
| **明确不做** | 把 ② 继续往"低延迟主路"方向投入;以及把"证书 + 重启 Steam"放回默认路径 |

## 6. 回退触发器(什么情况下改回 ①)

满足任一条,即把默认切回 ① 并把 ③ 降为可选:

1. 免 Key 上游连续 **14 天**不可用,或 `ACAO` 被移除(以 `poc/sim` + 真机 S4 复跑为准);
2. 引擎更新后 **S1 / S2 / S4** 任一红(公网页加载 / hash 回环 / CORS),且 3 天内无法修复;
3. 出现"要求消息不出本机"的用户群(隐私/合规诉求);
4. 托管侧单点故障导致可观测的批量失联(≥ 2 次/月)。

反向:若 ① 的证书安装流失率被证实高于阈值,则停止把 ① 列为推荐路径。

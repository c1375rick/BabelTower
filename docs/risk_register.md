## 2. 逐项验收标准(评审调整后的口径)

### 1. B6 原子写 —— 已完成,边界分析定案

- **已覆盖**:源码钉(零直写 configPath)/ 实现钉(tmp+fsync+rename+降级直写+清 tmp)/ 沙箱功能(新建、覆盖、stale tmp 收走)/ EPERM 降级底线 / 真实路径冒烟(POST `/api/v1/config` 纯重写,值 before/after 递归深等、无 .tmp 残留)。
- **并发覆盖边界(评审要求,分析定案)**:
  - 避免半截 JSON ✅:同目录 tmp → fsync → 同卷 rename,读者只会看到旧完整或新完整。
  - 避免并发覆盖 ⚠️ 语义区分:同进程内 `save()` 为同步写(writeFileSync→renameSync),Node 单线程天然串行,不可能交错出半截;跨进程(双实例/外部编辑器)为 last-writer-wins,原子 rename 只保证**任一读者不见半截**。串行写队列/锁/版本仲裁属另一个问题,当前无此并发场景 —— 若出现须另立工作项。
  - 掉电持久化:fsync 保证 rename 前数据已落盘;承认 rename 后目录元数据落盘前的极端窗口,不过度承诺。
- **验收差距处置**:「连续保存」可补护栏(低价值,待办可选);「进程中断(kill)」测试不采纳 —— Windows 下时序易抖,结构上半截只可能出现在 tmp,主文件恒为旧完整或新完整,由实现钉保证。

### 3. transport 加固 —— 代码完成,实弹验收未完

- **根因裁定**:桥侧处理正常(TRQ dt 55~854ms)—— 评审怀疑的「日志读取积压 / 事件循环阻塞 / 桥侧背压」被数据**排除为主因**;根因 = 下行 128 位组装在引擎 console.log 洪峰下丢位 → CRC 连败进风暴 → 回声 1 帧 8s 死线先到 → 拥塞误判掉线。
- **分类口径(现有日志字段即可分,无需新增埋点)**:原始 CRC 错误 = `RETRY` 行 `frameFails`;重试触发 = `consec≥2 → STORM enter`;重试成功 = `STORM exit` / `CRC ok`;风暴会话 = enter/exit 对。
- **最小修复(不越界)**:`State.btipcLastStormAt` + 回声拥塞豁免(15s 窗内 timeout/crc_dead 只记拥塞日志不判 down);8s 死线、STORM 常数、冻结文件**全部不动**。

### 6. 随包 Node 运行时的安全补丁线(2026-10-22)

- **风险**:发行包自带 `portable-node/node.exe`,用户拿到的是**我们打包那一刻**的 Node。
  Node 的安全公告是独立于本仓版本的 —— 1.2.0 ~ 1.2.1 随包的是 26.1.0,2026-10-21 公告后落后 11 个补丁版。
  桥是**长驻本机 HTTP/TLS 服务**(8791/8792)且会主动出站连 provider,运行时本身就是攻击面。
- **本次处置**:升级到 v26.12.1(官方包 + SHASUMS256 校验),随 1.2.2 出。
- **残余风险(逐条核对,见 checklist §18.6)**:不触 dns.resolve / Brotli / ZipFile / Permission Model /
  crypto.randomUUID → 那几条 high 漏洞在本仓**不可达**;仍有两条沾边:
  ① keep-alive 应答错配(medium)—— 影响是翻译/配置串味,不是 RCE;
  ② TLS 主机名校验绕过(high)—— 需先攻破 DNS/hosts 或用户自填 baseUrl 才能 MITM。
- **纪律**:`portable-node/` 不进 git,所以**版本不会随 git log 留下痕迹** —— 每次发版必须在
  release 记录里写明随包 Node 版本(诊断脚本 `diagnose_babeltower.ps1` 会打印它,可作核对);
  看到 Node 安全公告时,先查本仓是否触及对应 API,再决定是否要重新打包。
